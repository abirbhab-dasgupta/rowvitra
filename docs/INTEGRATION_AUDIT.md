## Route and control trace

`components/dashboard/dashboard.tsx` and `components/workspace/workspace-client.tsx` own the authenticated controls. Better Auth handles sign up, sign in, Google sign in, password change and sign out through `lib/auth-client.ts` → `/api/auth/[...all]` → `lib/auth.ts`/Postgres. The platform layout requires a session. All dataset routes call `requireUser`; `loadDataset` scopes dataset IDs to the session's user before reading versions. Mutations now check the configured same origin.

| Control | Request and server path | Processor/storage/response and UI state |
|---|---|---|
| Dashboard list and upload | `GET/POST /api/datasets` → `app/api/datasets/route.ts` | GET filters `datasets.userId`; POST validates extension/size, calls `/v1/profile`, uploads authenticated Cloudinary CSV, then inserts dataset and original version. Returns `{datasets}` or `{id}`; dashboard navigates to workspace. Failed DB transaction attempts asset cleanup. |
| Workspace load and goal | `GET/PATCH /api/datasets/:id` → `app/api/datasets/[datasetId]/route.ts` | GET returns current verified CSV, versions, rules and saved charts; PATCH updates goal for the owner. Workspace profiles on load and offers a manual recheck after goal change. |
| Profile and suggestions | `POST /api/datasets/:id/process` with `action: profile/suggest` → `/v1/profile` or `/v1/suggest` | Auth and version check, verified current CSV, then pandas profile or Gemini proposal. UI shows issues and the returned `gemini`/`rules` mode; fallback is now labelled `rules` when AI proposals fail validation. |
| Repair queue, preview, impact, approval | Same route with `action: preview/impact-chart/commit`, `versionId`, `operations`, and chart `spec` when needed → `/v1/preview` or `/v1/impact-chart` | Processor validates whitelisted operations and applies persisted rules. Preview returns diff, rule results, CSV and signed `approvalToken`. Commit recomputes and verifies the exact approval, uploads a snapshot, then transactionally compare-and-swaps the active version and writes an audit event. UI queues operations, displays preview and refreshes version/CSV on success. **Frontend token forwarding is pending coordination.** |
| Data contracts | Same route with `action: rules/save-rule/delete-rule` | `rules` checks browser proposals through `/v1/rules`; save validates shape, count, column and values before persisting; delete removes matching dataset/column/type rules. UI currently updates rule state optimistically without rollback on failure. |
| Editor and source rows | Same route with `action: rows` → `/v1/rows`; cell edit queues `edit_cell` for preview/commit | Processor caps selection and page size. Chart click row IDs are queried only against the authorized current version. UI table uses React text rendering; edits are never saved directly. |
| Charts | Same route with `action: chart/chart-advisor/save-chart` → `/v1/chart` or `/v1/chart-advisor` | Processor validates chart type, columns, filters and aggregation and computes values; save now validates the chart before storing its spec. Saved-chart selection currently changes the form but does not rerun the chart request. |
| History and replay | `POST /api/datasets/:id/restore` with `baseVersionId,versionId`; process `action: replay` with `newCsv` → `/v1/replay` | Restore verifies target hash before compare-and-swap and audit event. Replay uses the persisted recipe and original snapshot as its reference on a second synthetic CSV, returning warnings and preview only. UI refreshes CSV/version after restore. |
| Exports | `GET /api/datasets/:id/export?format=csv\|python\|audit` → `app/api/datasets/[datasetId]/export/route.ts` | CSV is the verified active snapshot; Python is generated from the original and persisted operations with replay verification; audit includes version hashes/events. Browser navigates to download URL; error bodies are not surfaced inside the workspace. CSV formula-like values are preserved and the UI warns about spreadsheet interpretation. |

`app/api/demo/process/route.ts` is a separate, rules-only sample path and is disabled unless `ENABLE_PUBLIC_DEMO=true`; it is not authenticated journey evidence.

## Confirmed findings and changes

| Severity | Finding | Resolution/state |
|---|---|---|
| P0 | Commit trusted browser-supplied rules and could approve a changed selection without a fresh preview. | `app/api/datasets/[datasetId]/process/route.ts` now reads persisted rules and checks a signed preview token bound to user, dataset, version, operations, rules and output hash (`lib/preview-approval.ts`). The one-line workspace token forwarding is pending frontend coordination. |
| P0 | Client-supplied `checkpoint` could alter row identity semantics and skip protected-column comparison. | Preview, impact and commit now reject submitted checkpoints; persisted recipes retain internal checkpoints for replay/script export. |
| P0 | A cell edit could grow a valid upload beyond the later storage read limit, making the committed version unreadable. | Processor preview now rejects output CSV above 1.5 MB before any upload; the output-size regression failed before the fix and passes after it. |
| P1 | Restore could switch the active version before detecting a missing/corrupt target asset. | `app/api/datasets/[datasetId]/restore/route.ts` downloads and hash-checks target first. |
| P1 | Upload/commit DB failures left Cloudinary assets orphaned. | `lib/storage.ts` and both mutation routes attempt authenticated asset deletion after transaction failure. If cleanup itself fails, a generic server log records it; manual Cloudinary inventory is still needed for recovery. |
| P1 | Chart/rule inputs could cause processor 500s or silently ignore rules after the 50th; negative pagination was silently clamped. A rule whose column was missing could incorrectly allow commit. | `services/processor/rowvitra/engine.py` rejects malformed/big filters and titles, invalid ranges/allowed values, excess rules and invalid pagination, and marks missing rule columns invalid in previews. Tests added in `tests/test_api.py` and `tests/test_engine.py`. |
| P1 | Gemini fallback could be labelled `gemini` when all model proposals were rejected, and provider exception text was returned to clients. | `services/processor/rowvitra/ai.py` returns `rules` mode and a generic notice; synthetic provider tests added in `tests/test_ai.py`. |
| P1 | Saved chart specs were accepted without processor validation; dataset mutation routes lacked an explicit origin gate; generic DB/provider errors were returned to clients. | `save-chart` checks the spec with `/v1/chart`; `lib/dataset-access.ts` gates mutations by origin and maps unexpected errors to generic responses. |
| P1 | Processor network/timeout errors and malformed successful responses were not classified as service failures; malformed request JSON could return 500. | `lib/processor.ts` now returns a service error; `lib/dataset-access.ts` maps JSON syntax errors to 400. Transport checks use mocked responses. |
| P1 | Cumulative approved recipes over 30 operations could not be replayed or exported as Python even though each approved batch was valid. | Processor now keeps the 30-step batch limit and accepts up to 300 persisted recipe steps for replay/script verification; commit rejects a recipe that would exceed 300 before upload. No schema migration. |
| P1 | Rule add/remove UI state is optimistic even if persistence fails; selecting a saved chart does not run its query; download failures navigate to JSON rather than showing an in-page error. | Frontend coordination required; exact file is `components/workspace/workspace-client.tsx`. |
| P2 | Public demo has no shared abuse limiter if enabled; Python target is 3.12/3.13 but the available local interpreter is 3.14. | Demo should remain disabled on public deployment. Local Python tests run on 3.14; deployment target remains unverified. |
